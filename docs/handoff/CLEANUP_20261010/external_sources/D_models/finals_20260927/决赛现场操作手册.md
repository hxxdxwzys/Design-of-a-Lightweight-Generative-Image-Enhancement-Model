# 决赛现场操作手册（20 组新 4K 图 · 现场算分）

> 用途：2026-10-17/18 东莞松山湖决赛现场，**现场处理 20 组新测试图并现场算分**。本手册是操作清单，不是方案介绍。
> 状态：**草案**。所有数字为【实测】，来源 `docs/progress.md` §42 与 `D:\tmp_timing\` 落盘读数。
> ⚠️ 现场环境（GPU 型号/显存/是否联网/是否允许预训练权重）**UNKNOWN**，见 §5 未知清单。

---

## 1. 一句话流程

```
新 4K LQ 图 20 张
  └─► infer.py --input <目录> --output <输出目录>
        └─► 512 分块 + 32 重叠 + 羽化拼接，JPEG q98/subsampling=0 输出
              └─► 交付 output_dir/case*.jpg（与输入同名）
```

## 2. 环境要求（必须现场核对）

| 项 | 要求 | 我们的实测 | 备注 |
|---|---|---|---|
| GPU | 单卡 NVIDIA，**显存 ≥4 GB** | RTX 4060 Laptop 8 GB，峰值 ~1.1 GB | 余量很大；CPU 也可跑通但慢 |
| CUDA | 12.x 驱动 | torch 2.7.0+cu126 | `requirements.txt` 只列 torch / numpy / Pillow |
| Python | ≥3.10 | 3.13.0 | `runner.py` 仅依赖 torch |
| 磁盘 | 20 张 4K 输入 + 输出 ≈ **1.5 GB** | — | 输出 JPEG q98 约 5–9 MB/张 |
| 联网 | **不需要** | — | ⚠️ 见 §5-③ |

## 3. 操作步骤（逐条可执行）

```powershell
# 0) 自检（必须做，约 3 分钟：512 路径合法性 + 用随包样例复现 4K 出图并逐字节比对）
python selfcheck.py
#    期望：case3 与 case17 两个样例“逐字节一致”
#    若 FAIL：不要继续，先查 §5-①

# 1) 官方口径 512×512 时延自测（约 1 分钟，预热 45 s + 40 次，每次前后 GPU 同步）
python infer.py --timing --iters 40 --preheat 45
#    期望：median ≈ 6.5–7.5 ms（依现场 GPU 而定，绝对值不重要，相对值才重要）

# 2) 出图（20 张约 40–60 秒；单张实测 1.88 s）
python infer.py --input <新图目录> --output <输出目录> --pattern "*.jpg"
#    注意：输入若为 png 需改 --pattern "*.png"；输出统一保存为 .jpg

# 3) 核对产物
#    - 数量 = 20
#    - 文件名与输入一致
#    - 尺寸与输入一致（同分辨率 1x，非超分）
```

## 4. 时间预算（【实测】推算）

| 步骤 | 耗时 | 依据 |
|---|---|---|
| selfcheck | ~3 min | 2 张 4K 重渲染 + 2 张 512 |
| 512 时延自测 | ~1 min | 45 s 预热 + 40 次 |
| **20 张 4K 出图** | **~40–60 s** | 单张 1.88 s（渲染 1.55 s + 存盘/读盘） |
| 合计 | **≈5 min** | 含环境加载 |

> ⚠️ **不要现场跑全量指标**：`clipiqa` 1.02 s/张、`niqe` 0.20 s/张尚可，但 **`musiq@4K` 42.8 s/张**（20 张 = 14 min）。若评委要求本地复算，**先说明口径与耗时**。

## 5. 未知清单与风险处置

| # | 风险 | 处置 |
|---|---|---|
| ① | **selfcheck 报 FAIL** | 先看是否"数组级 max≤12 且 mean≤1.0"（JPEG 有损往返的正常幅度）。**若逐字节不一致但数组级接近**，说明现场 GPU 的 kernel 选择与我们的机器不同 ⇒ **继续出图**，但**如实向评委说明**："我们机器上是逐字节一致的，此处差异来自 GPU kernel 数值差异，最大 N/255。" **不要隐瞒、不要说成通过。** |
| ② | 现场 GPU 显存不足 | 降 `infer.py` 里的 `TILE`（512 → 384/256）并同步把 `OVER` 减半。**注意：实测 512 块是最优档**（768/1024 块会让 clipiqa 掉 0.05–0.13），所以**这是降级方案、不是等价方案**。 |
| ③ | 现场无网 | 我们的包**不联网**（`HF_HUB_OFFLINE=1` 已在工具里设置，`runner.py` 无下载调用）。⚠️ 但 `pyiqa` 首次使用会尝试下载权重缓存 —— **若要现场算指标，事先把 `~/.cache/torch/hub/pyiqa` 拷到现场机器**。 |
| ④ | 现场要求用**他们的** runner 接口 | 我们严格实现了 `Runner(model_dir).infer(image_tensor, prompt="")`，输入输出 `[1,3,H,W] ∈ [-1,1]`。若他们传 `prompt` 字符串，我们**忽略之**（我们无文本条件）。 |
| ⑤ | 现场重测时延且读数偏慢 | **不要辩解**。如实给本地与现场两个数，并说明本地口径（预热 45 s + 每次前后 GPU 同步 + 取中位数）。⚠️ 本机笔记本 GPU 功耗受限，**持续满载会降频**：单次同步中位 ~7 ms，而连续 100 次只同步一次的均摊读数 ~10–15 ms。**这个差别要主动说，否则会被认为在遮掩。** |
| ⑥ | 现场要求解释权重来源 | 见 `docs/handoff/P10007`。一句话：**自研**，训练数据为公开高清图 + 按测试集退化分布在线合成配对，**无任何外部服务/修图软件**。 |

## 7. 出图质量的一句话诚实定位

> 我们的 4K 出图在**无参照感知指标**上明显优于输入（clipiqa 0.28→0.81、niqe 7.81→4.86），
> 在**有参照保真**上 PSNR 略低于输入（25.79→23.15）——**这是感知增强任务的固有取舍**：
> 增强越强，无参照观感越好、有参照保真越低。我们给出的是**可调工作点**与完整实测，不声称全面占优。
> 官方感知指标的具体构成与权重**以官方公布为准**，我们不对官方口径作任何假设。
