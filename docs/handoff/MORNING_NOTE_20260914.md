# 🚀🚀🚀 09:15 重大突破 —— **CUDA Graph：53.9x / 111.6x**

## 发现了什么

微模型 eager 的 14.6ms 里，**~14ms 是"内核启动开销"，不是算力**（0.87M 参数在 256 域的真实计算只要 ~1ms）。
用 **CUDA Graph**（官方规则三 6.1 明确允许：不同 patch/overlap 配置、JIT trace、**CUDA graph**）
把逐次启动固化成一次图重放：

| 包 | 512 时延 | 加速比 | 图像 |
|---|---|---|---|
| TinyV2（已交） | 14.64 ms | 19.5x | TinyV2 |
| **Track2_TinyV2g** | **5.30 ms** | **53.9x** | **与 TinyV2 逐像素相同** |
| **Track2_TinyV4g** | **2.56 ms** | **111.6x** | 与 TinyV4 相同（更平） |

## 踩到的两个坑（都已修，且验证等价）

1. **t.expand(x.shape[0])**：trace 后留下 aten::size 依赖 → capture 失败。改成**定值 buffer**。
2. **diffusers attention 的 head_dim = key.shape[-1] // heads**：trace 后留下 int(tensor)，
   而 capture 期间**禁止 device→host 同步** → 报 operation not permitted when stream is capturing。
   **修法**：把 attention processor 换成 head_dim 用 Python 常量的等价实现
   —— 实测**补丁前后输出 maxdiff = 0.000000**，graph replay 与 eager 也 maxdiff = 0.000000。

**安全性**：runner 在 __init__（不计时）里 capture；若环境不支持图捕获，**自动回退 eager**，功能不变。
