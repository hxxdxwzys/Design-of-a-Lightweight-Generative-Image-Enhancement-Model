## 2. 📐 已量化的轴（**仍是推断**，但有多点实测支撑）

### 2.1 速度（两个方向都测过，全部"同图只改时延"）

| 对照 | 加速比变化 | 分数变化 | 斜率 |
|---|---|---|---|
| M24 → avg2（图几乎相同） | 0.780x → 0.382x | 43.6951 → 36.6414 | **6.85 / 翻倍** |
| avg2 → Slow8（图逐字节相同） | 0.382x → 0.098x | 36.6414 → 28.7538 | **4.00 / 翻倍** |
| **M24 → Slow8**（图**逐字节相同**） | 0.780x → 0.098x | 43.6951 → 28.7538 | **4.98 / 翻倍** |
| TinyV2 → TinyV2g（图**逐像素相同**） | 19.5x → 53.9x | 29.4225 → 33.2872 | **2.63 / 翻倍** |

⇒ **1x 以下 ≈ 5~6.9 分/翻倍；1x 以上 ≈ 2.6 分/翻倍。曲线在 log 尺度上凹。**

### 2.2 ⭐ 质量项的真正形状（本日最重要的模型修正）

| 图像 | 测试集 clipiqa | val GT（512 裁切）clipiqa |
|---|---|---|
| M24（幻觉多、很锐） | **0.9023** | 0.8466 |
| **真值 GT 自己** | — | **0.3895** |
| PixRestore-b（保真好、很平） | 0.3055 | — |
| LQ（原图） | 0.2752 | 0.2136 |

**⇒ 无参指标（clipiqa 类）奖励的是"锐/纹理多"，不是"接近真值"**（真值自己的 clipiqa 只有 0.39，而 M24 的幻觉图有 0.85）。
**⇒ 官方评分不可能以无参指标为主**（否则"把 GT 原图当结果交"都会不及 M24，对一个复原赛题是荒谬的）。
**⇒ 有参指标（对私有的 test GT）必然是主战场 —— 而这是我们唯一无法本地测量的量。**

**这解释了为什么**：我们整周的质量干预（全是无参指标）几乎不动分；以及为什么 43.7 → 217 的差距不可能来自速度。

## 4. ⚠️⚠️ AI 容易犯的错（用户明确要求**重点强调**）

### 4.1 把 n=1/n=2 的读数外推成规律（**本日最大失误**）
- 我用 avg2/Slow8 两点算出"1x 以下 5~6.9 分/翻倍"，**外推**到 1x 以上，预测 40x 能到 70~80 分。
- 实测（TinyV2→TinyV2g）：**1x 以上只有 2.63 分/翻倍**，我高估了 **4 倍**。
- 代价：3 发提交 + 6 小时 GPU，造出一个 +4 分、质量掉 14 分的模型。
- **纪律：外推必须先声明区间与假设；不要超出拟合区间 1 倍以外下结论。**

### 4.2 凭空给世界加设定（**第二严重**）
- 我把榜单上 8 月的分数当成"旧机制遗留、不可比"，整段对话都在错误参照系里讨论。
- **用户纠正：全榜同一套规则，217 是当前规则下可做到的。**
- **纪律：任何"世界设定"（旧/新机制、口径不同、不可比）都必须先向用户确认，不许自己推断。**

### 4.3 用"未经因果验证的代理"行使否决权
- 我用 clipiqa < 0.45 否决了 v5 的提交；但 clipiqa **从未被验证为因果轴**——事实上**真值 GT 自己的 clipiqa 只有 0.3895**。
- 正确做法：**占据"新格子"的候选应该交**（信息量 > 1 发提交）；只有与已测格子重复时才省。
- **纪律：本地代理只能用于"排除明显退化"，不能用来否决一个新方向的候选。**

### 4.4 把本地指标当官方代理
- 试过 9 个：niqe / clipiqa / musiq / psnr / ssim / lpips / dists / lapvar / LFdiff —— **没有一个能解释跨模型家族的分数差**。
- **纪律：本地指标只用于"训练门控"和"排除崩坏"；提交决策靠"新格子 + 预登记判据"。**

### 4.5 代码 bug 造成假结论（本日踩了 7 个，别再踩）
1. subprocess.run(text=True) 不指定 encoding → Windows 用 GBK 解码 UTF-8 → **UnicodeDecodeError**（曾让我误以为 HYPIR 没跑完，白等 40 分钟）
2. np.stack 混了 256/512 两种尺寸的图 → v5/v6 训练第一步崩
3. torch.compile 在 Windows 无 triton → 必须 TORCHDYNAMO_DISABLE=1
4. range(1,101,4) 只有 25 个元素 → --n 100 只出了 25 张图（浪费 40 分钟 GPU）
5. GAN 脚本漏了把 512 蒸馏对降采样到 256 → 按 512 训练，4 倍算力/显存顶格
6. 内联 python -c 里的 % 格式化 → 链子崩在最后一步（**测量类脚本一律独立成文件**）
7. 磁盘幻觉：以为 D 盘充足，实际被 4.8G(PixRestore) + 8.9G(TADSR) 塞到只剩 6.5GB
8. **时延读数污染**：链子在前序任务刚跑完（GPU 未空闲）时测时延 ⇒ v7gan 读到 8.44ms/33.8x，空闲复测 **4.62ms/61.9x**（TinyV2g 记 53.9x，空闲 60.9x）
   ⇒ **判决性测速必须空闲复测**；否则会把速度轴收益低估 ~14%，v7gan 那档低估 1.8 倍

### 4.6 其它纪律
- **验证新模型前，先跑通"官方参考路径"对照**（PixRestore 就是这么确认 0.0155 差异 = fp16 级）
- **说区间，不说点估计**；**先写判据，再提交**
- **遇到意外结果，第一个问题永远是"我漏测了什么 / 我哪里写错了"**
