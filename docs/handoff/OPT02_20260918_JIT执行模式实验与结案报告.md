# OPT-02 报告（Implementer → 用户）：JIT 执行模式实验未达标且冷启动更差 → **不交付，保留 OPT-01（45.0509）**

> 背景：用户反馈 OPT-01 官方总分 **45.0509**（高于 A2 的 42.2145 与历史 M24 v3 的 43.6951），并授权继续自主优化。本轮按「先测量 → 预登记 → 有效轮对照 → 达标才出包」执行；结论是**不再交付新包**，并给出本地优化空间的收官判断。

## 1. 起点与瓶颈（FACT）

- OPT-01（全 fp16，`0a10f2c4…`）官方分 45.0509；A2（混合精度）42.2145 保留为保底；历史 M24 v3 43.6951。
- OPT-01 的 512 稳态分段（冻结模式、实测）：**dit 38.3%~40.2%**、encode 26%~28%、decode 25%~26%、features 7.3%、post 0.8%（c1 313.0 ms / c7 304.9 ms / c25 292.7 ms）。
- 结论：剩余时间全在数值计算里；可动的只有执行模式或数值路线。

## 2. H1 假设与实验（预登记后执行）

- **H1**：把交付 runner 的 `torch.jit.optimized_execution(False)` 改为 `True`（PyTorch 默认的 profiling executor）可带来 ≥10% 的 512 稳态改善，且输出变化远小于跨精度变更。**只改 runner**，模型与 OPT-01 逐字节相同（硬链接同文件）。
- 有效轮对照（A = OPT-01，B = 变体，同进程交错、冻结模式、先扣后跑）：

| 轮次 | 顺序 | 三输入中位数均值改善 | 逐输入改善 | p90 | 漂移 | 判定 |
|---|---|---|---|---|---|---|
| 1 | ABBA | **+12.00%** | c1 +7.14%、c7 +11.96%、c25 +16.59% | 全部改善（−3.7%~−24.1%） | 1.98% | 有效（但未过模块内更严的逐输入 ≥10% 判据） |
| 2 | BAAB | +6.74% | — | 通过 | **5.17%** | INVALID（漂移超限） |

- 输出差异（变体 vs OPT-01，五个样本）：**非逐位一致**；uint8 最大通道差 3~11 级、至少一通道不同的像素 12.8%~18.3%、4K case1 有 494 个元素 ≥4 级。量级与已交付的跨精度变更相当（OPT-01 vs A2：max 3~20 级、12%~23% 像素）。
- 同输入重复：逐位一致（repeat_max_abs = 0.0）。
- **冷启动**：变体首调 **2,444 ms / 2,715 ms**，OPT-01 首调 **1,044 ms / 438 ms** → profiling executor 首次调用多出约 **1.4~2.3 s**（profile + 融合）。

## 3. 处置：不交付（三条独立理由，任一成立即不应交付）

1. **未过预登记门槛**：要求两轮有效轮均 ≥10%；实际一轮有效（+12.00%）、一轮漂移超限（+6.74%）。
2. **指标错配风险**：官方测速条件 UNKNOWN；若其测量包含冷启动或调用次数很少，变体的首调开销（+1.4~2.3 s）会**吃掉甚至超过**稳态收益（+7%~12%）。
3. **代价/收益不对称**：为不足 12% 的稳态收益，付出与「跨精度」同量级的输出变化（质量影响本地不可测），而 OPT-01 已经把这条收益吃掉（+6.72% 总分）。

## 4. 本轮消耗与结论

- OPT-02 独立池：top **303/500**、4K 3/115、组件 0/5、监督 274.7 s / 14,400 s；**未出 100 图、未打包、未上传**；OPT-01 的 ZIP/模型/100 图与 A2 全部原样保留。
- **收官判断**：本地可做的优化空间已基本用尽——512 时间 38%~40% 在 DiT、51%~54% 在 VAE 编解码（均已 fp16），执行模式类改动的稳态上限约 7%~12% 且伴随冷启动劣化与数值扰动。
- **下一步只可能来自新领域**（均需新的预算与决策，本包不预授权）：① 质量轴（数据/训练或蒸馏，需数天 GPU 与质量判据）；② 采样/步数策略（本预设为一步蒸馏模型，多步是否有益无证据）；③ 若平台确按历史最佳计分，可用少量提交探测「质量-时延」换算，但需要可解释的候选，不能盲试。
