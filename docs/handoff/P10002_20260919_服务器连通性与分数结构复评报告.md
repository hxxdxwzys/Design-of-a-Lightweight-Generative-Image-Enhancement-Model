## 3. 512 测速路径剖面 + 执行侧三条新杠杆（本轮新增【实测】）

交付 runner（OPT-10，冻结模式，3 输入 ×（2 预热 + 10 计时））：

| 输入 | enc | feat | dit | dec | post | 墙钟 | **CUDA event GPU busy** |
|---|---|---|---|---|---|---|---|
| c1_512 | 85.0 | 21.9 | 116.7 | 83.4 | 3.4 | 311.6 | **312.1** |
| c7_512 | 85.2 | 22.0 | 117.8 | 83.0 | 3.4 | 313.2 | **314.1** |
| c25_512 | 86.2 | 22.3 | 117.1 | 83.3 | 3.5 | 313.5 | **314.2** |

- **GPU busy ≈ 墙钟（差 −1.1 ms）⇒ CPU / kernel launch / IPC 开销 ≈ 0**。CUDA Graph、CPU 向量化、去同步、算子缓存**在结构上都没有收益**（这条正式关掉了「还有非数值开销可挖」的猜测）。
- 三条**从未试过**的杠杆实测：
  - `channels_last`（模型 + 输入）：**慢 12.0%**（enc +18%、dec +34%），且输出 u8max=8 ⇒ **否决**；
  - `torch.jit.optimize_for_inference`：会**剥掉 encode/features/step/decode/post 属性**（`AttributeError: 'RecursiveScriptModule' object has no attribute 'encode'`）⇒ 与交付接口不兼容；
  - `cudnn.benchmark=True`：−1.0%（噪声级，且冻结模式下被覆盖）。
- **native（不设冻结开关）304.0 ms vs 冻结 317.5 ms ⇒ 确定性开关代价仅 4.2%**，且**注意力已是融合实现**（全模型 1610 个子模块中 **72 个使用 `scaled_dot_product_attention`**，无显式 softmax）⇒ 不存在「冻结模式掩盖 flash 后端」的漏判。
- ⇒ 512 路径是**纯算力**（DiT 36% + VAE 编解码 54% + DINO 7% + 后处理 1%），fp16 已吃满；再降精度（fp8/int8）在 torch 2.7 + sm_89 上**对 conv 无可用内核**、对 linear 的收益折算到总分 ≤3% ⇒ 不值得。
