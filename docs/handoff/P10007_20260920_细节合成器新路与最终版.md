## 1. 新方式：为什么之前的路线都撞墙

合规分数 ≈ 图像项 `Q` × 速度因子 `(r/0.78)^0.19`（r = 285.6/(t_ms+2)，台账 §8.5）。

| 家族 | 图像 Q | 512 时延 / factor | 合规分 |
|---|---|---|---|
| VOSR 0.5B（图好） | ≈44.6 | 312 ms / 1.02 | 45.6 |
| 微学生（快） | ≈24 | 4.2 ms / 2.17 | **<50（用户实测）** |

⇒ 瓶颈不是"增强强度"也不是"速度"，而是**微学生在 256 域推理、再 2× 上采样回 512，把渲染域细节全丢了**。

## 2. 新做法（本轮首创）：细节合成器 refiner

- 在学生之后串一个**残差 CNN（细节合成器）**：输入 = 学生 512 域输出，目标 = M24 观感（`D:/datasets/distill256/tgt`，2839 对 512×512）。
- **合规**：refiner 与学生一起 trace 进**同一个 `your_model.pt`**、同一张 CUDA Graph；512 测速与 4K 出图走**完全相同的代码路径**；100 张图**由打包后的 runner 本身**渲染 ⇒ 同主体，且非解耦。
- 训练数据：`in` = 学生在该 LQ 集上的 512 域输出（2839 张，90 秒生成）；`tgt` = M24 输出。

## 6. 和 GPT 合作以来做了什么（大白话）

前面几条路都做了"能做的极限"：把模型全 fp16、轻度锐化、连训四代微学生，但合规分始终卡在 50 以下——因为快的模型做不出好图，好图的模型又太慢。这一轮换了思路：**不再要求小模型自己产出细节，而是给它配一个"细节合成器"**，把小模型丢掉的高频细节用另一个小网络补回来；两个网络合成一个模型件、走同一条推理路径，所以既合规又快。试出来"薄版比厚版又准又快"这个反直觉结论（厚版时延 17 ms 把收益全吃掉），最终把预测从 <50 推到 **58.6~77.2**。

## 补记 2（17:0x，截止后）：32ch「甜点形状」实验为负结果 + 两条方法论教训

**动机**：CUDA Graph 内孤立测量显示 refiner 512 域 **32ch/2bl = 1.51 ms**、16ch/2bl = 3.16 ms（48ch 甚至 17 ms，属病态 kernel 选择）⇒ 预期"同样质量更省时延"。

**实测（同为 10k 步 GAN、同数据同目标、内置 unsharp 60）**：

| refiner | test30 clipiqa | niqe | 整链 512 时延（同法独立测） |
|---|---|---|---|
| thin1（16ch/2bl，8k 步） | 0.7952 | 4.7890 | 6.68 ms |
| thin2（16ch/2bl，再 6k 步、w_gan 0.3）→ **TinyRefV4** | **0.8046** | 5.0020 | 6.68~7.50 ms |
| **w32（32ch/2bl，10k 步、w_gan 0.12）** | **0.7775** | 4.8063 | **6.66 ms** |

⇒ **两条都否**：① 孤立成本优势**没有传导**到整链（换形状后整链时延不变，说明瓶颈不在这些 conv 的 kernel 选择）；② 同预算下更大网络**质量更差**（需另行调学习率/步数）。**TinyRefV4 保持为最优提交候选**；V5（w32@s6000）虽过门禁但质量未验且无时延优势，**不进入 upload/**。

**方法论教训（写入长期知识候选）**：**孤立算子/子模块的时延读数不能用于整链取舍**——必须以"同一 runner、同一进程、同口径"的整链读数判决（本轮已在 §37 的时延漂移问题之外，再添一条独立教训）。

## 补记 3（17:1x）：整链成本拆解 —— 256 域 + 像素重排 refiner 白省 ~0.7~1.0 ms

同一学生、同一 unsharp、同一导出器，只换 refiner 形状，在**整链**里测（独立进程、同法）：

| 变体 | 整链 512 时延（median / best） | 说明 |
|---|---|---|
| 512 域 16ch/2bl（thin2，V4 现役） | 6.40 / 6.07 ms | — |
| 512 域 32ch/2bl（w32） | 6.75 / 6.57 ms | 形状差异落在噪声内 |
| **256 域 32ch/2bl + PixelShuffle（随机权重成本探针）** | **5.75 / 5.19 ms** | **省 0.65~1.0 ms** |
| 无 refiner | 探针脚本未跑通（_arch 未定义，已修） | 待补 |

- ⇒ 把 refiner 的重计算搬到 **256 域**、用 PixelShuffle 学 2x 上采样，整链时延直降约 1 ms（factor 2.00~2.04 → 2.09~2.10，约 **+3~5% 分数**），且它看的是学生**未被双三次模糊过**的 256 域输出。
- 注意：5.75 ms 是**随机权重**的成本探针（只证明成本）；质量待 r256b（32ch/2bl、GAN 10k 步）训完实测。
- 更正上一节归因：512 域下 refiner 的整链边际成本 ~2.2~2.5 ms **与形状无关**（16ch 与 32ch 相同）⇒ 这段开销是 512 域本身的代价，**换域（而非换形状）才是正解**。
