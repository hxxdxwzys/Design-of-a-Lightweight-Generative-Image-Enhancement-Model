## 5. 勘误（对 PIPE-01 交付报告的更正；不改写原 handoff 正文）

### 5.1 JIT 静态障碍清单逐条纠正（原报告 §8）

| 原条目 | 原表述 | 更正 |
|---|---|---|
| §8-1 | peft 包装必须合并否则不可导出 | 合并是**简化路径**，不是"否则不可导出"的定理；peft 层含数据依赖分支，需实测 script/trace 行为 |
| §8-2 | script 不接受 forward 属性赋值 → 不可导出 | 部分成立：trace 可追踪实例属性绑定；script 需显式方法与类型注解。**不是不可导出的证明** |
| §8-3 | DINO 不适合脚本化 | 未验证的静态风险；hub 加载路径不进 forward 图；可 script 性需实测 |
| §8-4 | AutoencoderKL / DiagonalGaussianDistribution 不可 script | 未验证的静态风险；from_pretrained 构造不需进图 |
| §8-5 | 分块 Python 控制流需固定网格 | TorchScript scripting 支持带类型的动态控制流；变长网格可否 script 需实测 |
| §8-6 | wavelet 不能进 TorchScript | 准确表述：**当前 Python/PIL/NumPy/cv2 实现**不能直接作为纯 TorchScript 调用；**算法本身未必不可张量化** |
| §8-7 | trace 会固化随机输出 | **错误**：trace 记录张量操作，随机算子不必然变成常量；但采样式 trace 有非确定性校验风险，应显式传 noise 便于成对验证 |
| §8-8 | trace 固定所有 shape | 部分成立：由 Python 计算的 shape 会被固化，但不必然固定所有 shape |

新增需核查项（原清单遗漏）：RoPE 与 shape 转换、容器缓存、副作用、CPU 与 GPU 及 uint8 舍入、cv2 边界与核大小、
运行版本/算子/自包含依赖、save 后 load 的验证与 trace 重复执行的预算。
**导出目标**按裁决采用保守的"完整数值链可追踪"方案：可研究多子模块组成单一 ScriptModule；仅 DiT 导出只算内部阶段成果；
wavelet 若保留 Python 侧，必须两入口一致执行、完整计时，并取得官方依据；**当前不作合规承诺**。

### 5.2 失败次数与预算更正
原报告称第 2 次失败"0 前向"，并据此写"合计确定为 8 次"。**该表述作废**：
第 2 次失败发生在 budget.tick（当时位于 infer 之后），按执行位置**高置信推测已消耗 1 次真实前向**；
但当时无计数落盘、无 traceback 保存，**无法证明**，故本次按**保守方式记账：累计 9/10 次**（8 次确认 + 1 次保守预留）。
墙钟约 322.9 秒（三次 attempt 内部计时之和）。新的总账机制保证此类情形今后**必然被计入**。

### 5.3 旧 23 项测试的真实覆盖与生成器缺陷
- 旧 23 项只覆盖判定逻辑与 mock 路径，**未覆盖**：DINO 数值顺序、weights_only、身份完整性、预算扣减时机、
  量化前 NaN、计时口径、唯一产物。本次新增 26 项补齐（总 49）。
- 审查发现的缺陷已修：旧 make_evidence 会在检查 run 目录**之前**改写 evidence/hashes.json 与 key_contract.json；
  现在先检查、后写入，且有负测试断言被拒绝时零写入。

### 5.4 预登记的三份副本
三次 attempt 各有一份预登记，逐字段比较**只差 generated_at**，阈值/预算/资产/源码声明相同。
这支持"各次登记早于对应产物、未见阈值放宽"，但**不支持**"同一文件在整个 GPU 过程从未修改"。
本次已把**实现源码指纹**纳入预登记并在加载前强制比对，使"事后换代码"可被阻断（此前不能）。

### 5.5 工具标签更正
旧 evidence/summarize_run.py 被描述为"只读汇总器"，但它会向 run 目录写 summary.txt —— **标签不准确**。
该文件属已交付只读证据，本次未改动；新的机器可读执行器与矩阵生成器明确声明各自的写入位置。
