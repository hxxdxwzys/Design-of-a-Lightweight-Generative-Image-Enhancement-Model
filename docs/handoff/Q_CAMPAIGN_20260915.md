## 6. 首轮筛选结果与修正（2026-09-15 16:00）

### 6.1 首轮的三个产出
1. **接缝实测（有效数据）**：baseline(sc0.8/t512/wavelet) 竖缝 **1.054**、横缝 1.006；sc1.2 → 1.055/0.998；**adain → 1.049**/1.005
   ⇒ **换尺度、换色彩对齐都修不掉接缝** ⇒ 接缝来自渲染机制本身，不是模型参数。
2. **旧世界 val 渲染的接缝对照（CPU 免费测）**：seed_ensemble/{s108,s208,s308,avg4} 与 sweep_scale_val/pred_sc0.8 竖缝 **0.89~1.04**，**基本无接缝**。
   ⇒ 那些 val 渲染用了**不同的 VAE 分块参数**（生产 test 渲染用 vae_tile_size 1024 / vae_tile_overlap 64）
   ⇒ **【推断】接缝真凶可能不是"latent 随机噪声"（台账的旧判断），而是 VAE 分块** —— 这是可修参数。

## 7. Q2 热点定位与收尾状态（2026-09-15 16:50）

### 7.1 【实测】M24 runner 的 op 级热点（`q2_profile.py`，6 次 infer 合计）

| 组件 | CUDA 时间 | 折合每次 | 说明 |
|---|---|---|---|
| conv2d（cudnn 813ms + cutlass 407ms + …） | 1.87 s | ~310 ms | **VAE 的活** |
| group_norm | 0.60 s | ~100 ms | 同上 |
| linear / addmm / bmm | 0.80 s | ~133 ms | 0.5B DiT 的活 |
| **to / copy_** | 0.54 s（**5124 次调用**） | **~90 ms，854 次/次** | **fp16↔fp32 搬运，明显浪费** |

**结论：VAE（conv+groupnorm）比 0.5B DiT 更重。** 合法提速手段（规则明文允许 JIT trace / CUDA graph / 不同 patch）：CUDA Graph 固定 512 形状捕获 + 统一 dtype。
