## 2. 四项必须返修：处置与证据

### 2.1 A 只读复跑实际存在副作用 —— 已修

**问题**：默认入口调用真实子工具，会删除并重建共享目录并运行模型前向；--stage-upload 报拒绝后仍继续调用子工具；
交付报告 §9 却把它称为只读复跑。

**返修**

1. **默认改为计划模式**：不加 --execute-tools 时**不调用任何子工具**；工具行全部记 NOT_RUN，
   并输出 SIDE_EFFECTS_NOT_EXECUTED。计划模式下只做无副作用的本地只读检查（打开 zip、抽 3 张解码）。
2. **--execute-tools 显式启用**，启用时先打印副作用清单（harness 会 rmtree+重建解压目录、
   在该目录 import runner 做 512 前向、可能使用 CUDA；③④ 依赖该目录）。
3. **--stage-upload 拒绝后立即停止**：不执行任何检查、不调用任何子工具、不触碰任何目录，退出码 2，
   输出 STAGE_UPLOAD_UNAUTHORIZED。
4. 旧报告 §9 的可选命令已加**勘误**：不要执行。

**证据**：test_24（计划模式 executor.calls 为空）、test_23（拒绝归位 executor.calls 为空）、
test_25（CLI 计划模式下 stub 哨兵文件不存在）、test_11（CLI --stage-upload 时 stub 未执行、
upload 目录快照一致）、test_26（--execute-tools 时 stub 确实被执行，证明开关有效）。

### 2.2 B --sim-dir 未绑定真实产物 —— 已修

**问题**：--sim-dir 只改变后续检查目录，不传给负责解压的 harness，可能检查另一个包的旧目录；
原测试预建目录掩盖了该缺口。

**返修**：③④ 执行前必须通过三条**绑定证据**（全部满足；fail-closed，绝不退回“目录存在即用”）：

1. 该目录下存在 model_dir；
2. 该目录在**本次** harness 调用期间被重建（mtime 变化；原先不存在视为新建）；
3. harness 自报的 [1] 解压 OK: output_dir=N 与本包实际 output_dir 成员数**一致**。

任一条不成立 → ③④ 记 NOT_RUN，且**不调用**遮蔽脚本。真实 harness 把解压目录硬编码为
D:/models/_harness_zip_sim 且不接受目录参数，因此把 --sim-dir 指到别处时第 2 条通常不成立，
直接 NOT_RUN（这正是原缺口场景）。CLI 另会提示该硬编码事实。

**证据**：test_21（旧目录存在但未被重建 → ③④ NOT_RUN 且遮蔽脚本未被调用）、
test_22（harness 报 99 而包内 100 → NOT_RUN，输出“解压产物与包不匹配”）、
test_22b（缺 [1] 行 → NOT_RUN）、test_06b（目录缺失 → NOT_RUN）。
测试不再预建 sim 目录：由 harness stub 真的去重建它。
