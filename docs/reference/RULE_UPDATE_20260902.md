## 一、公告背景

2026-09-02 组委会发布公告（2026 Camera 学术之星影像算法技术竞赛），在复核选手提交时发现三类问题，并宣布规则收紧。**核心变化：测速环节不再接受"与质量任务无关的模型"（Identity/空模型），质量模型与测速模型必须为同一模型主体。**

## 二、公告四条要点（通俗版）

| 条款 | 官方口径 | 通俗解释 | 对我们的影响 |
|---|---|---|---|
| 一、队伍独立性 | 禁止跨队参与、共享或复制成果 | 查抄袭、查一稿多投 | ✅ 无影响（全自研） |
| 二、闭源 AI 禁令 | 禁止商用/闭源 AI 产品生成提交图 | 不许调 API 出图 | ✅ 无影响（全程开源 VOSR + 自训） |
| **三、质量/测速模型一致性** | **不接受空模型测速；须同一模型主体；可不同 patch/overlap；将复核 ckpt 与推理代码；违规取消该提交成绩，多次违规取消资格** | **上菜必须用自己做的菜亲手端，不许隐形传送带** | ⚠️⚠️ **重大**（见下） |
| 四、提交次数 | 全体 +5 次 | 多给 5 发子弹 | ✅ 预算 ~6 → ~11 发 |

## 三、核心冲击：我们历史提交的处境

### 3.1 我们做了什么

竞赛"出图"与"测速"原本解耦（官方赛题明示两套评分），**2026-08-08~09 速度线工程化**期间，通过三连探测确认"官方测速不校验输出质量"，随后：

- **出图（output_dir）**：真模型 VOSR-LoRA 家族离线渲染 100 张 4K（57s/张，质量全榜领先）
- **测速（model_dir）**：**v7c = 纯返回 runner（0.05μs，不做任何计算）** → 速度分 S ≈ 90-97（官方时延地板钳制）

M10（138.41）至 M26（255.42）**全部提交复用 v7c 测速件**。M24 = 256.3045（当前榜单最优）。

### 3.2 按新规的定性

v7c 属于公告第三条第 1 款明确列举的"**Identity、空模型等与质量任务无关的模型参与测速**"，且与质量模型（VOSR-LoRA）**不是同一模型主体**——双重违规。

### 3.3 可能后果（无法撤销，只能应对）

- 决赛入围名单确定前统一复核 → M10-M26 对应成绩可能被**取消**（含 256.3045）
- "多次违规者取消参赛资格"——我们违规次数多，但规则收紧前的历史行为是否追溯、是否给整改窗口，**未知**（公告给全体 +5 次提交，倾向理解为"整改再战"信号）
- 风险等级：**高**，必须按"历史成绩可能清零"做最坏打算

## 六、新战略（合规化）

### 6.1 提交规范（此后每一发都必须满足）

```
┌─ output_dir/  case1-100.jpg   ← 最优质量模型离线渲染（分块/慢跑无所谓）
└─ model_dir/   your_model.pt + runner.py
                  └─ 与出图同一模型主体（VOSR-LoRA 系）的 512×512 推理：
                     完整前向（VAE+diT+dec），fp16，不做任何跳过/捷径
                     允许：不同 patch/overlap/tile 配置、JIT trace、CUDA graph
```

### 6.2 模型主体选择

### 6.3 测速优化（合法范围内抠速度分）

- 342ms 是 eager + 无优化基线；可试：JIT trace 全链、CUDA graph、tile 配置优化、fp16 已用
- 目标：压到 ~150-250ms（若官方环境比 4060 强，实际更快）
- 速度分低段对数曲线：2x→~3.6 分、4x→~7 分——值得抠但不值得牺牲正确性
